The Groundwork Guide / Layer 1
LAYER ONE

Data Readiness.

Get it out of your head: digitize, name, and file what your business knows.

Why this layer comes first

AI can only work with what it can read. Most of what your business knows lives in filing cabinets, email threads, and one person's memory. Layer 1 moves it into files a machine can search: scanned, named consistently, and filed in a structure that makes sense without a tour guide.

This is the exact system I built for my own properties in Lafayette before I ever taught it to anyone. It is not glamorous. It is the foundation everything else in this program stands on. A consistent naming convention means any person, or any AI, can find any document instantly.

The naming convention

Every file you create follows one universal formula. No exceptions, no personal styles, no "I'll remember what this is."

YYYY-MM-DD_[CODE]_[Description].pdf

Date

The document date, not the scan date. ISO format: year, month, day. A lease signed March 15, 2024 starts with 2024-03-15 even if you scan it in 2026.

Code

A 3-letter document type code from the standard table below. LSE for a lease, INV for an invoice, INS for an insurance certificate.

Description

A brief, specific identifier: vendor name, client, property, project. Hyphens between words. Acme-Landscaping-Annual-Service, not contract stuff.

Build one by hand

Three moves. Pick the document date. Pick the code. Write a short hyphenated description. Join the parts with underscores.

Date:         2024-06-15
Code:         CTR
Description:  Vendor-Name-Service-Type

Result:       2024-06-15_CTR_Vendor-Name-Service-Type.pdf

If you type spaces in the description, replace them with hyphens before you save. Spaces break sorting, scripting, and some sync tools.

Five golden rules

  1. Always use the document date, not the date you scanned it.
  2. Never use spaces in filenames. Use hyphens within words, underscores between parts.
  3. Keep descriptions under 5 words. Be specific but concise.
  4. Always use .pdf as the extension. Scan everything as searchable PDF.
  5. When in doubt, check the code table. If no code fits, use GEN (General).

The five-step workflow

Every document follows the same path from physical paper to AI-ready data: Scan, Name, File, Upload, Verify. Follow this process for every single document, every single time. Consistency is what makes the system work. McKinsey research on standardized document workflows found they cut processing time by 60 percent and error rates by 75 percent.

Step 1: Scan / Digitize

  • Set the scanner to 300 DPI minimum (600 DPI for fine print).
  • Use color mode for documents with highlights or color-coding.
  • Enable OCR (Optical Character Recognition) in your scanner software.
  • Output format: searchable PDF, not image-only PDF.
  • Capture the entire document. No cut-off edges.
  • Flatten stapled packets. Scan multi-page documents as a single PDF.

Step 2: Name the file

  • Use the universal formula: YYYY-MM-DD_[CODE]_[Description].pdf.
  • Date = the document date, not the scan date.
  • Code = the standardized document type code (LSE, VND, INS, and so on).
  • Description = a brief, specific identifier: client name, vendor, project.
  • Hyphens within description words, underscores between parts.
  • Example: 2024-03-15_CTR_Acme-Corp-Service-Agreement.pdf.

Step 3: File in the correct folder

  • Go to the correct top-level category folder.
  • Place the file in the right subcategory (for example, Contracts > Active).
  • If unsure, check the folder templates further down this page.
  • Never leave files in a "misc" or "unsorted" folder.
  • One document = one file. Don't combine unrelated documents.
  • If a document belongs in two categories, file it in the primary one and note the cross-reference in your log.

Step 4: Upload to your system of record

  • Open your management system or cloud drive (Google Drive, OneDrive, Dropbox).
  • Go to the correct folder, client, or project record.
  • Upload the file to the right document section.
  • Verify the file name matches what you saved locally.
  • Confirm the upload completed successfully.
  • Check that the file opens correctly from within the system.

Step 5: Verify and log

  • Open the uploaded file and confirm it's readable.
  • Spot-check: can you select and copy text? That confirms OCR worked.
  • Log the document in your weekly scanning log spreadsheet.
  • Note any issues: poor original quality, missing pages, and the like.
  • Mark it complete in your daily task list.
  • If you find quality problems, re-scan before moving on.

Day one: prove the loop works

On your first day, complete one full cycle with a single document. Pick something simple, a one-page vendor invoice or an insurance certificate. Follow all 5 steps, then ask your AI a question about that document. When it answers correctly, you have seen the entire system working end to end. That is the proof that the work matters.

Here's how that looked for one operator, Sarah. She started with a single vendor invoice, a one-page document from her office supply company. She scanned it at 300 DPI with OCR, named it 2024-01-15_INV_OfficeMax-Supplies.pdf, filed it in 02_Financial/Invoices-Paid/, and uploaded it to Google Drive. Total time: 4 minutes. Then she asked the AI: "How much did we spend on office supplies in January 2024?" It answered correctly, citing the exact invoice. That's when she knew the system worked. By the end of week one she had processed 30 documents, and the AI could answer questions about all of them.

Knowledge check

Confirm you have the workflow down before moving on. Answer each one in your head, then open the expander.

What is the correct order of the 5-step workflow?

Scan, Name, File, Upload, Verify. You must digitize the document first, then name it properly, file it in the right folder, upload it to your cloud system, and finally verify it's readable.

What should you do if you can't select or copy text from an uploaded PDF?

Re-scan with OCR enabled. If you can't select text, OCR didn't work. The AI literally cannot read image-only PDFs. You must re-scan with OCR enabled to create a searchable PDF the AI can actually process. Renaming or re-uploading changes nothing.

When naming a file, which date should you use?

The document's original date. Always use the date on the document itself, not the date you scanned it. This keeps everything chronologically accurate when the AI searches for documents by date.

Quality standards

The difference between a useful scan and a useless one comes down to a few simple settings. The AI reads the text from your scans. If it can't read the text clearly, it gives wrong answers.

What good looks like

  • 300 DPI minimum resolution (600 DPI for fine print or legal documents).
  • OCR enabled. Text must be selectable, not just an image.
  • Full page captured. No cut-off margins or missing corners.
  • Straight alignment. Not rotated or skewed.
  • Clean glass. No smudges, streaks, or shadows from the scanner lid.
  • Color mode for documents with highlights, stamps, or color-coding.
  • Single PDF per document. Multi-page documents combined into one file.

What to avoid

  • Low resolution (below 200 DPI). Text becomes blurry and unreadable to AI.
  • Image-only PDF with no OCR. The AI sees a picture, not text it can read.
  • Cropped or cut-off pages. Missing information the AI needs.
  • Skewed or rotated scans. OCR accuracy drops hard.
  • Dark shadows or smudges. They obscure text and confuse character recognition.
  • Grayscale mode on color documents. It loses important visual information.
  • Multiple unrelated documents in one file. It confuses categorization.

The 30-second quality check

After every scan, run through this list before moving on:

  • Can you select and copy text from the PDF? (Confirms OCR.)
  • Is all text sharp and readable at 100 percent zoom?
  • Are all pages present? Check the page count.
  • Is the document straight, not rotated?
  • Are there any dark shadows or smudges?
  • Does the filename follow the naming convention?

Edge cases and exceptions

Real documents aren't always clean single pages. Here is how to handle the tricky ones.

ScenarioHow to handle it
Multi-page stapled documentsRemove staples, scan all pages as a single PDF. Re-staple the original after scanning.
Double-sided pagesUse duplex scanning if available. Otherwise scan front, then back, and combine into one PDF in correct page order.
Oversized documents (blueprints, site plans)Use a large-format scanner if available. Otherwise photograph in sections with overlap, or send to a print shop for professional scanning.
Handwritten notes or annotationsScan at 600 DPI in color. OCR will capture typed text; handwritten portions are preserved as images. Note in the scanning log that handwriting is present.
Documents in poor condition (torn, faded, water-damaged)Scan at the highest resolution in color. Adjust brightness and contrast if needed. Note condition issues in the scanning log. Do NOT discard the original.
Duplicate versions of the same documentKeep the most recent or most complete version. File the other in Archive with _SUPERSEDED appended to the filename.
Documents with sticky notes or attachmentsScan the base document first, then scan sticky notes and attachments separately. Combine into one PDF with attachments after the main document.
Envelopes with postmarks (date evidence)Scan the envelope as the first page, then the contents. The postmark date may be legally significant.

Confidentiality and data handling

  • Never leave scanned documents open on a shared or public screen.
  • Do not email unencrypted files containing sensitive financial or personal data.
  • Social Security numbers, bank account numbers, and personal financial data need extra care. Flag these for supervisor review.
  • When in doubt about whether a document should be digitized, ask before scanning.
  • All scanned data is subject to your company's data retention and privacy policies.

Version control

When a document is updated, a new lease version, a revised policy, an updated insurance certificate:

  1. Move the old version to the Archive folder.
  2. Append _SUPERSEDED to the old filename.
  3. Save the new version in the active folder with the current date.
  4. Note the replacement in your scanning log.

Never delete old versions. They may be needed for legal or historical reference.

Folder structure templates

Choose the folder structure that matches your business type. These templates give you a ready-to-deploy filing system. Every top-level folder carries a numbered prefix so folders always sort in the same order on any operating system.

Which template fits?

Three questions. Your answers point at a template.

1. What type of documents do you deal with most often?

  • Leases, tenant files, and property inspections: Commercial Real Estate.
  • Client case files, court filings, and research memos: Law Firm.
  • Patient records, insurance claims, and compliance documents: Medical / Dental Office.
  • Invoices, contracts, and general business paperwork: General Business.
  • Permits, vendor orders, and employee schedules: Restaurant / Retail.

2. Do you have regulatory compliance requirements?

  • Healthcare / HIPAA compliance: Medical / Dental Office.
  • Professional ethics and bar requirements: Law Firm.
  • Health department and food safety: Restaurant / Retail.
  • Minimal, standard business compliance only: General Business (or Commercial Real Estate if you manage property).

3. Who are your primary customers or stakeholders?

  • Tenants and property owners: Commercial Real Estate.
  • Patients and insurance companies: Medical / Dental Office.
  • Clients involved in legal matters: Law Firm.
  • Walk-in customers and suppliers: Restaurant / Retail.
  • Other businesses, clients, or a mix: General Business.

If two templates tie, pick the one from question 2. Compliance needs shape a filing system more than anything else.

How to set up

  1. Create the structure. Copy the tree straight from this page and build it by hand, or run one of the scripts in the next section to build it in one command.
  2. Put it in your preferred location. Desktop, Documents folder, or directly in your cloud drive (Google Drive, OneDrive, Dropbox).
  3. Rename the root folder. Change it from the template name to your actual company name.
  4. Test the structure. Save one sample document in each top-level folder to confirm everything works.
  5. Share it with your team. If you use a shared drive, set permissions so everyone can read but only designated people can reorganize.

Pro tips

  • Never create a "Miscellaneous" or "Other" folder. It becomes a dumping ground the AI can't navigate.
  • If a document could go in two places, file it in the primary category and note the cross-reference in your scanning log.
  • Review and clean up the Archive folder quarterly. Old documents still have value for AI training.
  • The numbered prefix (01_, 02_, and so on) keeps folders in the same order regardless of operating system.
  • Customize these templates to your specific business. Add subfolders as needed, but keep the top-level structure intact.

What comes next: the Intelligence Vault

This folder structure is your document filing system, where your actual files live. In Layer 3 you'll build a separate Intelligence Vault that sits alongside it. The vault holds entity files, relationship maps, decision logs, and governance rules that tell AI how to reason about your documents.

Think of it this way: Layer 1 organizes your documents so AI can find them. Layer 3 builds the knowledge layer so AI can understand them.

Setup scripts

You don't have to build the folder tree by hand. These scripts create the complete structure on your computer in one run. Both scripts build the same numbered layout; edit the company name variable at the top before running, and add or rename folders to match your chosen template.

macOS / Linux (Bash)

Creates the full numbered folder tree with one command on macOS or Linux.

#!/bin/bash
# ============================================
# AI-Ready Folder Structure Generator
# Works on macOS and Linux
# ============================================
# Usage: chmod +x create_folders.sh && ./create_folders.sh

# Set your company name here
COMPANY_NAME="My_Company_Documents"

# Create root directory
mkdir -p "$COMPANY_NAME"
cd "$COMPANY_NAME"

echo "Creating AI-ready folder structure for: $COMPANY_NAME"

How to run the Bash script

  1. Open Terminal (Mac: Cmd+Space, type "Terminal". Linux: Ctrl+Alt+T).
  2. Go to where you want the folders: cd ~/Documents
  3. Create the script file: nano create_folders.sh
  4. Paste the script above, then save (Ctrl+O, Enter, Ctrl+X).
  5. Make it executable: chmod +x create_folders.sh
  6. Run it: ./create_folders.sh

Scanning and OCR software

OCR (Optical Character Recognition) converts scanned images into searchable text, which is what the AI actually reads. Without OCR, your scanned PDFs are just pictures.

Windows

Quick recommendation

  • On Windows and want free: use NAPS2. It handles scanning and OCR in one step.
  • On Mac: start with the built-in Preview scanner. Move up to DEVONthink if you're building a serious knowledge base.
  • On Linux: use Simple Scan for the scanning step, then run everything through OCRmyPDF. For a full system, deploy Paperless-ngx.
  • Have budget and want the best: Adobe Acrobat Pro works on all platforms and has the highest OCR accuracy.

Troubleshooting

Something not working? Find your symptom below. Each entry explains what went wrong, how to fix it, and how to stop it happening again.

Can't select or copy text from the PDF OCR

Root cause: OCR was not enabled during scanning, so you have an image-only PDF the AI cannot read.

How to fix:

  1. Re-scan the document with OCR enabled in your scanner software.
  2. If you can't re-scan, use OCRmyPDF (command line) or Adobe Acrobat Pro to add an OCR layer after the fact.
  3. Verify the fix: open the new PDF and try to select and copy a word.

Prevention: Always confirm OCR is enabled before starting a scan batch. Check the first scan of each session.

Text is blurry or unreadable at 100 percent zoom Resolution

Root cause: Scanner DPI was set too low (below 200 DPI), or the original document moved during scanning.

How to fix:

  1. Re-scan at 300 DPI minimum (600 DPI for fine print or legal documents).
  2. Keep the document flat and stationary on the scanner glass.
  3. Clean the scanner glass to remove smudges or dust.

Prevention: Set your scanner default to 300 DPI. Check the first page of each batch before continuing.

AI can't find a document I know I scanned Filing

Root cause: The document was filed in the wrong folder, named incorrectly, or left in an unsorted location.

How to fix:

  1. Search your file system for the document by date or partial name.
  2. Check Downloads, Desktop, or any "Unsorted" folders.
  3. Once found, rename it using the correct convention and move it to the proper folder.
  4. Re-upload it to the cloud system if the file was only saved locally.

Prevention: Never leave files in temporary locations. Complete all 5 workflow steps before moving to the next document.

AI gives wrong or outdated information about a document Data quality

Root cause: An old, superseded version is still in the active folder, or the document was mislabeled with the wrong metadata.

How to fix:

  1. Check whether multiple versions exist. Move old ones to Archive with the _SUPERSEDED suffix.
  2. Verify the filename date matches the actual document date.
  3. Confirm the document type code is correct (CTR versus INV, for example).
  4. Re-upload the correct version and wait for the AI to re-index.

Prevention: When updating documents, always archive the old version first. Never overwrite files in place.

Scan has dark edges, shadows, or black borders Scanner

Root cause: The scanner lid was not fully closed, or the document didn't cover the full scan area.

How to fix:

  1. Close the scanner lid completely and re-scan.
  2. For thick documents or books, press down gently on the lid.
  3. Use your scanner software's auto-crop feature if available.
  4. If shadows persist, place a white sheet of paper behind the document.

Prevention: Always close the lid fully. Use auto-crop settings. Check the first page before scanning a batch.

PDF is missing pages from a multi-page document Scanning

Root cause: Pages were skipped during scanning, or the scanner's auto-document-feeder (ADF) jammed.

How to fix:

  1. Count the physical pages and compare against the PDF page count.
  2. Re-scan missing pages individually.
  3. Use a PDF editor to insert the missing pages in the correct position.
  4. Rename the final combined file. Don't create a separate "page 5" file.

Prevention: Always verify the page count after scanning multi-page documents. Listen for ADF jams.

File exists locally but not in the cloud Cloud sync

Root cause: The sync app is paused, the file is too large, or a naming conflict is blocking the upload.

How to fix:

  1. Check your sync app status (Google Drive, OneDrive, Dropbox). Look for pause or error icons.
  2. Verify your internet connection is active.
  3. Check for filename conflicts: special characters or very long names.
  4. Manually upload the file if auto-sync won't resolve it.

Prevention: Keep the sync app running at all times. Check the sync status icon daily. Avoid special characters in filenames.

Same document appears in multiple folders or with multiple names Organization

Root cause: The document was saved multiple times, or copied instead of moved during filing.

How to fix:

  1. Identify the correct, most complete version.
  2. Keep it in the primary correct folder with proper naming.
  3. Delete all duplicates, or move them to Archive if unsure.
  4. Note in the scanning log that duplicates were consolidated.

Prevention: Always MOVE files to their destination, never copy. File immediately after naming. Don't leave copies in temp locations.

Still stuck?

If your issue isn't listed here or the fix didn't work, escalate to whoever owns your system with these details:

  1. What you were trying to do.
  2. What happened instead (screenshot if possible).
  3. What you already tried from this page.
  4. The specific filename and folder involved.
